## 1. 范围与约束

### 1.1 范围

| 项 | 内容 |
|---|---|
| 星球 | 一颗母星（全产业链）+ 最多 5 座采矿前哨（仅采掘） |
| 生产模型 | 纯数值 + 时间推进，无空间布局，无传送带 |
| 战斗 | 玩家手动触发的锈群波次塔防 |
| 联机 | 单人经营 + 异步市场与排行榜，无玩家间对抗 |
| 终局 | 发射火箭 |

### 1.2 约束

1. 配方比例与配方时间 1:1 对齐 Factorio 2.0。
2. 每秒推进一次，不做子步。
3. 玩家操作全部为数值调整：分配槽位、调优先级、装模块、选载荷。

### 1.3 核心循环

```
采矿 → 冶炼 → 零件 → 科技包 → 研究 → 解锁新配方
  ↑                                    ↓
  └──── 扩产 ← 瓶颈诊断 ← 产线失衡 ←────┘
```

## 2. 世界观

### 2.1 回响循环

宇宙在回响中循环。每次循环末尾恒星熄灭，一切归零，然后从同一种子重新展开——相同的星图，不同的细节。

对应现有 `12 周目 × 16 星区 × 64 恒星系`。

### 2.2 玩家身份：记忆体

玩家是上一轮循环中把意识编码进种子舱、射入轨道、躲过归零的工程师。醒来时母星是荒原，上一轮留下残骸、遗迹与空转的旧设施。

每轮需重新造出火箭并把种子送出。发射成功则带着部分记忆进入下一轮。

### 2.3 四个派系

| 派系 | i18n key | 形态 | 玩家交互 |
|---|---|---|---|
| 矿业公会 | `miners_guild` | 市场经营者 | 挂单买卖材料 |
| 深核议会 | `deep_council` | 蓝图商 | 用暗物质购买破损蓝图 |
| 自由舰队 | `free_fleet` | 事件方 | 商队、劫掠、护航委托 |
| 锈群 | `swarm` | 塔防对手 | 挑战波次 |

### 2.4 设定对应

| 现有内容 | 新设定 |
|---|---|
| 遗迹 | 上一轮自己的工厂残骸，可拆解回收 |
| 未知信号 | 上一轮留下的信标，含数据或物资 |
| 虫洞 | 循环之间的裂缝 |
| 矿脉衰减 | 循环末期矿脉贫化 |

### 2.5 火箭

火箭是唯一能跨循环的物体。发射即把本轮成果写入下一轮。

## 4. 建筑体系

### 4.1 实例模型

每座建筑是独立实例，同类型可建多座。

```ts
interface BuildingInstance {
  id: string
  type: BuildingType
  level: number                 // 1~16
  slots: Slot[]                 // 长度 = 等级对应槽位
  modules: MaterialId[]         // 已装模块
  enabled: boolean              // 停用后不耗电、不产出、不计入合计
}

interface Slot {
  recipeId: string | null       // null = 空槽
  progress: number              // 0~1
  status: 'running' | 'starved' | 'blocked' | 'undervolt' | 'throttled' | 'idle'
  outputItem?: MaterialId       // 拆解类配方的随机产出，完成时写入
  techId?: TechId               // 实验室槽位绑定的科技
}

// Planet
buildings: BuildingInstance[]
```

| 规则 | 值 |
|---|---|
| 单实例等级上限 | 16 |
| 同类型实例数上限 | 8 |
| 单类型槽位上限 | 128 |
| 全星球实例数上限 | 96（超出时提示拆除） |

**合计口径**

解锁判定、产量加成、波次结算一律取合计值：

```
getTotalLevel(planet, type) = Σ 实例.level（仅 enabled）
```

塔防与电力受合计影响：

```
炮塔总 DPS   = Σ 各炮塔 DPS（按等级与弹种）
防线长度     = 基础值 + Σ 各城墙.level × 20 秒
装机容量     = Σ 各发电建筑输出（按等级）
```

**停用**

| 项 | 规则 |
|---|---|
| 电力 | 不消耗，发电输出不计入装机容量 |
| 产出 | 不产出 |
| 合计 | 不计入 getTotalLevel |
| 模块 | 保留在原实例上，不退回 |
| 槽位进度 | 保留，恢复后继续 |

停用场景：配方重新配置期间；供电不足时优先供给防御与关键产线。

**成本口径**

| 操作 | 成本 |
|---|---|
| 新建一座实例 | baseCost |
| 实例升到 Lv N | baseCost × 1.35^(N-1)（电力 1.6，发射井 2.0） |
| 拆除实例 | 返还 baseCost 的 50%（向下取整） |

**拆除**

| 项 | 规则 |
|---|---|
| 模块 | 全部退回仓库 |
| 槽位进度 | 丢弃 |
| 耗时 | 立即生效 |
| 实例数上限 | 不占用，拆除后可立即重建 |

**适配层**

数据结构替换前先落三个函数，收敛全部调用点：

```ts
getInstances(planet, type): BuildingInstance[]
getTotalLevel(planet, type): number
addBuilding(planet, type, level): BuildingInstance
```

### 4.2 等级与槽位

生产类建筑的等级决定槽位数量。每个槽位独立执行一个配方实例，速度受建筑速度与模块影响。

| 等级 | 1 | 2 | 4 | 6 | 8 | 12 | 16 |
|---|---|---|---|---|---|---|---|
| 槽位 | 1 | 2 | 4 | 6 | 8 | 12 | 16 |

空槽不消耗电力，不产出。

非生产类建筑的等级含义逐条定义在 §4.3 中。

| 蓄电器 | 储能 | 容量 |
| 核反应堆 | 烧核燃料棒发电 | 输出功率 |

#### 科研

| 建筑 | 功能 | 等级作用 |
|---|---|---|
| 实验室 | 消耗科技包推进研究 | 槽位；每槽指定 1 项科技 |

实验室槽位与生产建筑同构：每槽绑定 1 项科技，进度 = 该槽贡献的研究单位。同一科技可占多槽，进度叠加；未绑定科技的槽位空转，不消耗科技包；科技完成后其占用的槽位清空。

#### 军事

| 建筑 | 功能 | 等级作用 |
|---|---|---|
| 炮塔 | 消耗弹药输出伤害 | 伤害与射速；决定可用弹种 |
| 城墙 | 延长防线长度 | 防线 +20 秒/级 |
| 雷达 | 波次预演 | 情报层级 1~3 |

#### 物流

| 建筑 | 功能 | 等级作用 |
|---|---|---|
| 仓库 | 物品种类库存上限 | 单种上限 |
| 物流塔 | 流体吞吐上限 | 槽位 = 可接入的流体种类；每种流体 40 秒/级流量 |

#### 特殊

| 建筑 | 功能 | 等级作用 |
|---|---|---|
| 火箭发射井 | 发射火箭 | 装配速度 |
| 排空阀 | 销毁指定流体 | 槽位；每槽 5 单位/秒 |

### 4.4 成本曲线

```
cost(level) = baseCost × mult^(level-1)
mult = 1.35（生产） / 1.6（电力） / 2.0（发射井）
```

槽位翻倍级（2/4/8/16）为阶梯成本，非平滑曲线。

## 6. 运行机制

### 6.1 槽位分配

每个生产建筑各有 N 个槽位。玩家把槽位分配给该建筑支持的配方，同一配方可占多个槽位。一个槽位同时只跑一个配方实例。

```
装配机 Lv8（8 槽）
├─ 电路板   占 4 槽
├─ 铁齿轮   占 2 槽
└─ 空       2 槽
```

空槽不耗电、不产出。

**扣料时机**

```
进度推进至 1 时，检查并一次性扣除全部输入，同时产出。
输入不足：进度停在 1，状态 = 断料，不产出，不扣料。
```

**进度与切换**

| 操作 | 结果 |
|---|---|
| 切换配方 | 进度清零，无返还（未到 1 时尚未扣料） |
| 清空槽位 | 进度清零 |
| 建筑停用 | 进度保留，恢复后继续 |
| 库存堵塞 | 进度停在 1，输入未扣，恢复后立即产出 |

**槽位数量**

同一配方占多个槽位时，每个槽位独立计时、独立扣料、独立产出，产能线性叠加。

**分配面板**

装配机可跑 9 类配方中的 5 类，配方总数超过 40 条。槽位分配面板按类别折叠：默认只展开已有槽位分配的类别，其余类别折叠为一行标题加当前占用槽数。类别内配方按当前是否可生产排序，断料配方置底。

### 6.2 库存与堵塞

全部固体物品存于行星仓库，每种物品有独立上限（`仓库等级` 决定）。

```
若 当前库存 + 本次产出 > 上限：
    该槽位暂停，状态 = 堵塞
```

配方恢复条件：库存低于上限。

### 6.3 配给优先级

当某物品可分配量小于总需求时，按玩家设定的规则分配。

**排序键 = (物品, 消费配方) 二元组。** 玩家逐物品维护一张配方顺序表。

| 模式 | 规则 |
|---|---|
| 优先级 | 按表从上到下依次满足，高优先吃满，低优先闲置 |
| 比例 | 按各配方当前需求量等比分配，余数给排序靠前者 |

未在表中出现的消费配方排在末尾。

同一物品同一 tick 内被多个槽位竞争时，按上述顺序本 tick 内一次性分配完毕。

### 6.4 电力

```
装机容量 = Σ 发电建筑输出
实际需求 = Σ 活跃槽位能耗
满足率   = min(1, 容量 / 需求)
```

满足率小于 1 时，全部槽位按满足率同比降速。蓄电器在容量不足时补足缺口，电量耗尽后满足率归零。

太阳能阵列仅在白天输出。蓄电器容量跨昼夜结算。

### 6.5 流体

流体不进仓库，走管道。每种流体受物流塔吞吐上限约束：

```
每种流体容量 = 10,000 单位
若 需求流量 > 上限：
    相关槽位按 上限/需求 比例降速
```

### 6.6 副产物溢出

标记 `byproduct` 的产物库存已满时，该槽位暂停，其输入不再被消耗，上游随之堵塞。

排放分两级：

| 机制 | 触发 | 速率 | 产出 |
|---|---|---|---|
| 排空阀 | 玩家安装并指定流体 | 5 单位/秒/槽 | 无 |
| 安全排放 | 任一流体满仓持续 10 分钟 | 1 单位/秒 | 无 |

安全排放生效时，对应流体状态标记为「排放中」，并在诊断面板常驻提示。

**规则：任一流体不得因满仓而永久阻断上游配方。**

当前仅炼油链触发。

### 6.7 诊断面板

主界面为配方列表，每行一个配方：

| 字段 | 内容 |
|---|---|
| 配方 | 名称与图标 |
| 理论产能 | 秒产 |
| 实际产能 | 秒产 |
| 状态 | 正常 / 断料 / 堵塞 / 欠压 / 限流 / 无槽位 |
| 缺失项 | 导致当前状态的具体物品或条件 |

```
理论产能 = 槽位数 / 配方时间
实际产能 = 最近 60 秒该配方产出总量 / 60
```

面板每 2 秒刷新一次，数值变化用补间过渡；状态枚举变化立即刷新。

### 6.8 离线结算

1. 单次离线最多结算 12 小时，可用暗物质延长。
2. 离线不触发任何战斗。
3. 离线期间扰动正常累积。
4. 结算使用固定步长批量模拟，步长 60 秒。

**单步执行规则**

```
单步可执行次数 = min( floor(步长 / 配方时间), 由输入与仓容支持的最大次数 )
不足一次时不执行，进度跨步累积。
```

超出仓容的产出不产生，槽位置为堵塞状态，下一步重新判定。

### 6.9 矿脉衰减

| 储量 | 状态 | 效率 |
|---|---|---|
| > 40% | 正常 | 100% |
| 20%~40% | 贫矿 | 50% |
| < 20% | 贫化下限 | 20% |

储量不再降至 0。

### 6.10 模块

模块装入建筑，作用于该建筑全部槽位。

| 模块 | 效果 |
|---|---|
| 速度模块 | 速度 +20%，能耗 +50% |
| 产能模块 | 产出 +10%，能耗 +40% |
| 效率模块 | 能耗 −30% |

可插模块的建筑，模块槽位上限 = 建筑等级 / 4（向下取整）。

**安装与拆除**

| 操作 | 规则 |
|---|---|
| 装入 | 从行星仓库扣 1 个模块，填入该建筑的空模块槽，立即生效 |
| 拆除 | 模块退回行星仓库，立即失效 |
| 替换 | 先拆除再装入，不额外收费 |
| 上限 | 槽位装满后不可再装 |
| 拆除建筑 | 已装模块全部退回仓库 |

同类模块可叠加，效果按数量线性累加。

产能模块的产出加成按槽位累计：每完成一次产出，累计值加上该槽位的总加成百分比；累计值 ≥ 100% 时额外产出 1 个并减去 100%。小数部分不丢弃。

### 6.11 tick 顺序

每个 tick（1 秒）按下列顺序结算一次：

| 序 | 子系统 |
|---|---|
| 1 | 装机容量与需求统计，得出满足率 |
| 2 | 矿井、抽水站、油井产出 |
| 3 | 配方槽位推进，按满足率降速 |
| 4 | 产出写入库存，判定堵塞 |
| 5 | 研究推进，扣科技包 |
| 6 | 进行中的波次结算 |
| 7 | 前哨运输结算 |
| 8 | 任务与成就判定 |
| 9 | 差量下发 |

同一 tick 内产生的库存变化，在下一 tick 才参与分配。

### 6.12 产线模板

玩家可把当前星球的全部槽位分配保存为模板，用于批量套用。

| 项 | 规则 |
|---|---|
| 保存 | 记录每种建筑类型的配方槽位分布 |
| 套用 | 按类型匹配，逐实例自上而下填充，槽位不足部分留空 |
| 数量 | 最多保存 5 套 |
| 范围 | 仅母星，前哨不适用 |

## 7. 研究体系

### 7.1 结构

科技树分 6 层，共 42 项。研究由实验室消耗科技包推进。完整清单见 §13.9。

```
第 1 层  电力系统 → 自动化 ─┬→ 机械传动 → 装配技术 → 太阳能利用
                            ├→ 基础物流
                            ├→ 冶炼优化
                            └→ 采掘效率

第 2 层  钢材冶炼 → 引擎工程
         基础物流 → 基础军事 → 弹道学 / 装甲
                  → 雷达 / 物流塔 → 高级物流

第 3 层  化工 → 炼油工艺 → 塑料 / 硫磺 / 排空阀
         塑料 → 高级电路 → 处理单元
         塑料 + 硫磺 → 高级化工；硫磺 → 电池
```

## 8. 锈群塔防

### 8.1 结构

锈群波次由玩家手动发起。无定时触发，离线永不发生。

| 属性 | 规则 |
|---|---|
| 触发 | 玩家在「锈群前线」面板选择波次并确认弹药库存 |
| 奖励 | 掉落物工厂不可生产 |
| 成本 | 消耗弹药，即消耗产能 |
| 失败 | 损失本波已消耗弹药与冷却时间，不损失建筑与库存 |

### 8.2 流程

```
1. 打开「锈群前线」
   ├─ 扰动等级 / 可挑战最高波次
   ├─ 每波强度预估 / 所需弹药 / 掉落预览
   └─ 模式选择：观看 / 自动

2. 选择波次 → 校验所需弹种库存 → 开始

3. 逐波推进，波间 30 秒间隙

4. 结算：战报 + 掉落；首通成功不进入冷却，重复挑战与任意失败进入冷却
```

### 8.3 波间操作

波与波之间有 30 秒间隙，可执行：

| 操作 | 效果 |
|---|---|
| 补充弹药 | 从仓库调拨，按时长计入间隙 |
| 切换弹种 | 机枪 / 穿甲 / 炮弹 |
| 调用舰队支援 | 消耗一支在港舰队，按该舰队总攻击力折算等效 DPS；舰队全灭则损失 |
| 开启过载 | 炮塔射速 +50%，弹药消耗 +100% |

**舰队支援折算**

```
支援 DPS = Σ(舰船数 × 该舰种 attack) × 0.5
持续整场波次，不可重复调用
```

舰队全灭判定沿用现有 `battleLogic` 的损失计算，以本波剩余锈群 HP 作为对手机体。

**断线处理**

| 情况 | 处理 |
|---|---|
| 挑战中断线 | 波次暂停，推进与弹药消耗停止 |
| 30 分钟内重连 | 从当前波继续，间隙计时重置 |
| 超过 30 分钟未重连 | 本波判负，已消耗弹药不退，计入冷却 |

### 8.4 扰动与波次

```
扰动值 = 总能耗(MW) × 0.6 + 累计产量(万单位) × 0.1 + 建筑总等级 × 0.05
扰动等级 = clamp(floor(扰动值 / 8) + 1, 1, 8)
可挑战最高波次 = 扰动等级 × 5
```

扰动只决定可挑战上限，不触发任何事件。

强度曲线：

```
第 N 波 HP = 3000 × N^1.5 × (1 + 0.08 × 扰动等级) × 周目系数
周目系数 = 1 + 0.15 × (周目 − 1)
```

| 波次 | 扰动 1 | 扰动 8 |
|---|---|---|
| 1 | 3,240 | 4,920 |
| 5 | 36,224 | 55,007 |
| 10 | 102,458 | 155,584 |
| 20 | 289,794 | 440,058 |
| 30 | 532,386 | 808,438 |
| 40 | 819,662 | 1,244,672 |

表中为普通波基础 HP，按上式实算并四舍五入到个位。精英波与潮涌波在此基础值上另乘倍率：

| 类型 | HP 倍率 | 锈群残骸倍率 | 额外掉落 |
|---|---|---|---|
| 普通波 | ×1 | ×1 | — |
| 精英波（5 的倍数） | ×3 | ×3 | 神经索 |
| 潮涌波（20 的倍数） | ×3 | ×5 | 破损蓝图、锈群核心 |

| 波次类型 | 频率 | 特性 |
|---|---|---|
| 普通波 | 每波 | 标准 |
| 精英波 | 每 5 波 | HP ×3，锈群残骸 ×3，掉落神经索，需穿甲弹 |
| 潮涌波 | 每 20 波 | HP ×3，锈群残骸 ×5，掉落破损蓝图与锈群核心，需舰队支援 |

### 8.5 结算模型

```
每 tick（1 秒）：
  扣弹药：仓库对应弹种 -= Σ(该弹种炮塔等级 × 弹药消耗速率) × 过载弹药系数
  若某弹种库存归零，使用该弹种的炮塔本 tick 无输出
  锈群HP -= Σ(有弹药的炮塔DPS × 过载系数)
  锈群推进 += 1 / 防线长度

  锈群HP <= 0          → 本波胜利
  锈群推进 >= 1        → 本波失败
  全部炮塔连续 10 秒无输出 → 本波立即判负
```

```
防线长度（秒） = 40 + Σ 各城墙等级 × 20
```

弹药在 tick 内扣减，波次结束时不再额外扣减。

### 8.6 掉落

波次上限 40（扰动 8 × 5），精英波 8 次（每 5 波），潮涌波 2 次（每 20 波）。

| 掉落 | 来源 | 数量 | 上限内可得 | 需求量 |
|---|---|---|---|---|
| 锈蚀合金 | 每波首通 | 4~8（均值 6） | 240 | 200 |
| 神经索 | 精英波首通 | 3~6（均值 4.5） | 36 | 32 |
| 破损蓝图 | 潮涌波首通 | 3 | 6 | 6 |
| 锈群核心 | 精英波 +1 / 潮涌波 +2 | — | 12 | 12 |
| 循环残片 | 每波 | 1 | 40 | 不限 |
| 锈群残骸 | 每波 | (10 + 波次号) × 矿石方案倍率 | 1,900 | 不限 |

锈群残骸的倍率由矿石方案决定，见 §13.4。精英波 ×3，潮涌波按 ×5 计算、不与精英倍率叠乘。

**结构约束：锈群残骸只来自波次，不随工厂规模增长。** 拆解产出总量由残骸供给封顶，与采矿产能无耦合。

所有需求量均在 40 波内可满足，无需重复刷取。

| 任务统计 | 不计入战役中的「建筑总数」目标 |
| 战斗 | 不参与战斗，也不被攻击 |

前哨的建筑等级、槽位、配方规则与母星一致，仅限建筑白名单内。

### 9.7 前哨运输

前哨产物自动运回母星，无需手动派遣。

```
航线运力 = 分配至该航线的货船总货舱容量
往返分钟 = 2 × 航程距离 / 1000
每分钟运回 = min(前哨产量, 航线运力 / 往返分钟)
超出部分留在前哨仓库
```

| 项 | 规则 |
|---|---|
| 航线 | 每条前哨一条独立航线，固定方向为前哨 → 母星 |
| 货船 | 小型货船、大型货船；按**数量**从舰船池分配，可随时增减，不占舰队任务槽位 |
| 仓储爆满 | 前哨仓库满时该前哨停产，状态标记「待运」 |
| 回程 | 回程不载货，按往返时间计算 |
| 母星仓容 | 运回时按母星仓库余量判定；母星无余量则货物停在前哨仓库，状态标记「待转运」 |

运力由玩家造船决定，是工厂产出转化为舰船的主要消耗口。

### 10.3 目标类型

| 类型 | 判定 | 记法 |
|---|---|---|
| 达到产能 | 指定配方的实际产能 ≥ N/秒 | `铁板 ≥0.3/s` |
| 建成建筑 | 指定建筑实例数 = N | `矿井 ×1` |
| 建筑等级 | 指定建筑合计等级 ≥ N | `电炉 ≥8` |
| 建筑总数 | 全星球实例数 ≥ N | `建筑总数 ≥20` |
| 持有材料 | 指定材料库存 ≥ N | `煤 ≥300` |

| 通过波次 | 通过第 N 波 | `第 5 波` |
| 建立前哨 | 前哨数量 ≥ N | `前哨 ≥1` |
| 航线运力 | 全部前哨航线的合计运力 ≥ N | `航线运力 ≥5000` |
| 周目 | 周目数 ≥ N | `≥2` |
| 发射 | 火箭发射成功 | — |

删除的目标类型：`DefeatNPC`、`ReachRelation`、`SendGift`、`FormAlliance`、`DestroyPlanet`。

### 10.4 奖励

| 优先级 | 奖励类型 | 内容 |
|---|---|---|
| 1 | 解锁建筑 | 直接改变产线结构 |
| 2 | 稀有材料 | 锈蚀合金、神经索、锈群核心 |
| 3 | 建筑实例或等级 | 直接追加一座实例，或提升现有实例 |
| 4 | 资源 | 铁板、钢板等常规材料 |
| 5 | 暗物质 | 仅终章与周目任务 |

奖励中的配方与建筑若同时由科技与任务解锁，以先达成者为准；后达成的一方折算为等值资源，按基础价 × 20 折算为单位数。

奖励的建筑等级在实例已达 Lv16 时，折算为该建筑 baseCost × 20 的材料。

## 11. 角色体系

### 11.1 工程服

工程服提供装备网格，网格大小决定可装装备数量。

| 装备服 | 网格 | 造价 | 解锁 |
|---|---|---|---|

| 模块化工程服 | 10×10 | 低密度结构 ×20 + 处理单元 ×20 | 精密制造 |

工程服由装配机以 `equipment` 类别制造，替换即时生效。替换后旧工程服消失，已装装备按网格规则处理：新网格可容纳的保留原位，放不下的退回仓库。

### 11.2 装备

| 装备 | 尺寸 | 耗电 | 效果 | 成本 | 解锁 |
|---|---|---|---|---|---|

**个人电网**

```
个人供电 = Σ 发电装备输出
个人负载 = Σ 耗电装备消耗
个人储能 = Σ 电池容量
```

供电不足时优先用储能补足；储能耗尽后，按尺寸从小到大依次停用耗电装备。

**网格规则**

| 项 | 规则 |
|---|---|
| 旋转 | 不可旋转 |
| 重叠 | 不可重叠 |
| 越界 | 不可越界 |
| 同类装备 | 可装多个，效果按数量线性叠加 |
| 持有数量 | 仓库可存多个，未装入的不生效 |
| 工程服升级 | 超出新网格的装备自动卸下，退回仓库 |

## 12. 火箭与周目

### 12.1 火箭

```
火箭 = 火箭部件 ×100
1 个火箭部件 = 低密度结构 ×10 + 火箭燃料 ×10 + 火箭控制单元 ×10（3 秒 / 420 kW）
```

全程需 低密度结构 ×1000、火箭燃料 ×1000、火箭控制单元 ×1000。

### 12.2 载荷

载荷是独立物品（`PayloadId`），由装配机以 `payload` 类别制造，存于仓库独立计数区。发射时消耗。

| 载荷 | 制造配方 | 跨周目效果 | 发射时选择 |

| 种子舱 | 钢材 ×100 | 必需，解锁下一周目 | 自动 |

| 工业种子 | 低密度结构 ×50 | 保留 1 座建筑实例的等级 | 指定 1 座母星实例 |

| 星图阵列 | 处理单元 ×200 + 太阳能板 ×50 | 继承全部已发现星系 | 自动 |

| 项 | 规则 |
|---|---|
| 发射条件 | 火箭 ×1 + 种子舱 ×1，其余载荷可选 |
| 数量 | 同类载荷最多携带 1 份 |
| 消耗 | 发射时扣除对应载荷 ×1 |
| 未携带 | 该效果不生效，不返还成本 |
| 发射失败 | 不消耗载荷（发射为瞬时操作，无失败判定） |

### 13.8 科技包消耗

实验室规模参考：槽位总数 ≈ 最紧缺科技包的产能（个/秒），超出部分因包不足空转。

```
每秒消耗（每种包）= 实验室槽位总数
```

例：某科技需要红绿蓝三种包，实验室 Lv4（4 槽），则每秒消耗每种包各 4 个。

任一科技包库存为 0 时，研究按最短缺项降速。

### 14.3 容量基线

实测数据（合成状态，26 座建筑 / 180 槽位 / 55 材料 / 30 份战报 / 50 份任务报告 / 200 已发现星系）：

| 玩家数 | 存档体积 | stringify | parse |
|---|---|---|---|
| 10 | 0.83 MB | 6.8 ms | 6.0 ms |
| 100 | 8.0 MB | 56 ms | 43 ms |
| 1000 | 80 MB | 514 ms | 774 ms |

单人构成：

| 区块 | 体积 | 占比 |
|---|---|---|
| 战报 30 份 | 38.9 KB | 48% |
| 建筑与槽位 | 12.7 KB | 16% |
| 任务报告 50 份 | 11.4 KB | 14% |
| 已发现星系 200 个 | 8.7 KB | 11% |
| 材料库存 55 种 | 1.1 KB | 1.3% |
| 科技 42 项 | 0.4 KB | 0.5% |
| 单人合计 | 81.8 KB | — |

结论：工厂状态本身只占 12.7 KB，体积主要来自报告历史。

测量时材料为 55 种，当前设计 62 种，材料区块约增加 0.15 KB，不改变结论。

### 14.4 技术前置

**（1）报告上限**

| 类型 | 上限 | 超出处理 |
|---|---|---|
| 战报 | 30 | 最旧归档到 `data/archive/<playerId>/` |
| 任务报告 | 50 | 同上 |
| 通知类 | 20 | 直接丢弃最旧 |

无上限时单人可达数 MB，是全库唯一的无界增长点。

**（2）存档按玩家分片**

```
data/players/<playerId>.json   单人 82 KB，仅重写脏玩家
data/world.json                市场、星门、残骸、账号（全局，约 100 KB）
```

单次自动保存写入 1~3 个脏文件，耗时 < 2 ms。千级玩家仍维持在此量级，不引入 SQLite。

自动保存间隔 30 秒，仅在脏标记置位时写入。

**（3）同步粒度**

现状：`core/protocol.ts` 按 `Player` 顶层字段比对，`planets` 中任一数值变化会导致整个 `planets` 字段（含全部建筑与槽位）重发，约 15 KB / tick / 玩家。

改造：

| 层级 | 比对粒度 | 每 tick 体积 |
|---|---|---|
| `planet.resources` | 55 个数值 | ~1 KB |
| `planet.buildings[].slots` | 不下发，仅下发聚合成效 | ~0.3 KB |
| `planet.fleet` / `defense` | 变化时下发 | 0 |
| `self.discoveredSystems` | 变化时下发 | 0 |

改造后单玩家每 tick 上行约 1.3 KB，10 人合计 13 KB/s。

**（4）离线快进**

固定步长 60 秒批量模拟，单次上限 12 小时，即最多 720 步。
