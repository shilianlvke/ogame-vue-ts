## A 类 · 硬伤

### A1 电力自举死锁

矿井 90 kW/槽，火力发电厂需要煤，煤来自矿井。开局无电 → 无煤 → 无电。

文档中「手搓」只出现在 §12.1 进度表里，没有机制定义。

**修法**：三选一，建议第一种。

1. 矿井新增「燃煤模式」：Lv1~Lv2 不耗电、烧煤自供，Lv3 起转电驱。
2. 新增手搓配方：`铁矿 ×1 → 铁板 ×1`，冷却 5 秒，无能耗，上限 200 次。
3. 初始赠予煤 ×50 + 发电厂 ×1。

### A2 S0 阶段无机制

§12.1 的 S0「手搓铁板、石炉、第一块矿」在正文中无对应系统。

**修法**：与 A1 合并解决，S0 定义为「燃煤矿井 + 石炉」阶段。

### A3 副产物死锁（无自恢复）

轻油唯一出口是「轻油裂解 → 石油气」。若石油气满仓：

```
塑料/硫磺停产 → 石油气积压 → 轻油裂解停 → 轻油满 → 高级炼油停 → 重油断供
```

全链永久停机。玩家离线 8 小时后回来，油链已死机 7 小时，且不会自恢复。

**修法**：新增「排空阀」建筑或全局规则。

| 方案      | 规则                                        |
| ------- | ----------------------------------------- |
| 排空阀（建议） | 独立建筑 1 座，1 槽位/级；把指定流体按 5 单位/秒直接销毁，不产出任何东西 |
| 自动降级    | 轻油满仓时，裂解配方视为可用，但只产 0 石油气                  |
| 溢出烧毁    | 任一流体满仓超 10 分钟，按 1 单位/秒自动销毁                |

### A4 掉落量与波次上限算术矛盾

| 掉落   | 需求量 | 单波产量             | 所需波次    | 实际上限   |
| ---- | --- | ---------------- | ------- | ------ |
| 锈蚀合金 | 320 | 2~8（均值 5）        | 64      | 40     |
| 神经索  | 90  | 1~3（精英波，每 5 波一次） | 45 次精英波 | 8 次精英波 |

可挑战最高波次 = 扰动 8 × 5 = 40 波。精英波仅 8 次，最多产出 24 神经索，需求 90。

**修法**：重新标定，二者取一并同步到 §8.6 / §8.4。

```
需求 神经索 24 → 表改为约 20
需求 锈蚀合金 160 → 表改为约 160（32 波）
或 可挑战上限改为 扰动 × 10（最高 80 波）
```

### A5 锈群核心不在材料表

§8.8 用「锈群核心」作为高级科技与升级的货币，§3.3 材料清单无此物，MaterialId 也没有。

**修法**：加入 T10，来源「每 5 波首通 1 个」，需求量约 30。

### A6 离心机缺失

§3.3 T6 写「铀-238 / 铀-235 ← 离心」，§4.2 二十种建筑无离心机，§5.3 无离心配方。

**修法**：新增建筑「离心机」，1 槽处理 10 铀矿石 → 9.93 铀-238 + 0.07 铀-235（按期望值取整为整数比：`铀矿石 ×1000 → 铀-238 ×993 + 铀-235 ×7`，时间 60 秒）。

### A7 电解厂缺失，重水成为孤儿材料

§3.1 写「`deuterium` → 重水，来源电解厂」，但：

- §4.2 无电解厂
- §5.3 无制取重水的配方
- §3.3 材料清单无重水
- 所有配方都不消耗重水

**修法**：二选一。

1. 删除重水，`deuterium` 直接映射为「水」，旧存档重水按 1:1 折算为水。
2. 补全：电解厂（4 槽）+ 配方 `水 ×100 → 重水 ×1`（10 秒），重水作为「核燃料棒」的可选强化材料。

建议第 1 种，减少一条孤儿产线。

### A8 修复站功能悬空

§4.2 修复站「自动恢复建筑等级」，但 §8.9 明确「建筑降级：否」。战斗中建筑永不降级，修复站无用武之地。

**修法**：三选一。

1. 删除修复站，建筑仍不降级，补第 20 号建筑（建议「排空阀」，见 A3）。
2. 改为「维修站」：每波结束后按损失度恢复城墙耐久（配合 C5）。
3. 改为「超频站」：消耗电力为指定建筑临时提速。

建议第 1 种，与 A3 合并。

## C 类 · 结构矛盾

### C1 单母星 vs 行星间物流（已解决）

§1.1 定「单母星，一颗可经营星球」，§8.13 写舰队用途为「行星间物流」。没有第二颗生产星球，无货可运。

**决策：采用「采矿前哨」**，落地于规划书 §9.6 / §9.7。

### C2 单母星 vs 星图探索（已解决）

§9.5 列出遗迹、前哨、巢穴三类地点，但玩家没有离开母星的理由。星图退化为纯装饰。

**决策：同 C1。** 星图成为资源地图，矿脉按 biome 与经济类型分布，玩家为找矿而探索。NPC 侧的前哨改名为「贸易站」以区分。

### C3 建筑单实例 vs 多实例

现有代码 `buildings: Record<BuildingType, number>` 是每类型一座。后期需 24 条以上装配配方并行，而单座装配机 Lv16 只有 16 槽。

#### 实测改动面

| 指标                                                                                         | 数值                 |
| ------------------------------------------------------------------------------------------ | ------------------ |
| `planet.buildings` 引用总数                                                                    | 172 处              |
| 涉及文件                                                                                       | 38 个               |
| 其中位于待删文件（npcGrowthLogic 56 / BuildingsView 4）                                              | 60 处               |
| 其中位于待重写文件（resourceLogic 43 / buildingLogic 8 / buildingValidation 8 / waitingQueueLogic 3） | 62 处               |
| **需额外处理的存量文件**                                                                             | **50 处 / 约 20 文件** |

集中在：`shipValidation`(9)、`GMView`(8)、`planetLogic`(5)、`moonLogic`(5)、`commands`(5)、`ItemDetailView`(5)、`ResearchView`(3)、`GalaxyView`(3)、`researchValidation`(3)。

#### 七项对比

| 维度    | 单实例（`Record<Type, number>`）  | 多实例（`BuildingInstance[]`）      |
| ----- | ---------------------------- | ------------------------------ |
| 产能上限  | 每类 1 座，最高 16 槽；提至 32 槽可解，但见下 | 无上限，受电力与物流约束                   |
| 装配机容量 | 24 条配方争抢同一个槽位池               | 可分机专精，如 3 座各跑 8 条              |
| 调整影响面 | 改一次分配，全厂配方同时变动               | 只影响该实例                         |
| 升级路径  | 唯一：Lv8 → Lv16，成本 ×11.0       | 可选：再建一座 Lv8，成本 ×8.5；或升到 Lv16   |
| 玩家直觉  | 「这座机器要跑什么」——与工厂游戏习惯不符        | 「再建一座装配机」——符合直觉                |
| 等级语义  | 每类含义不同（槽位/功率/容量/特殊），C4 由此产生  | 统一为「该实例的槽位或强度」，总量靠数量叠加，C4 自动消失 |
| 塔防结算  | 炮塔仅一座，等级即全部火力                | 炮塔多座，总 DPS = Σ，更符合塔防直觉         |
| 数据结构  | 零改动                          | 新增实例数组，50 处存量引用需适配             |
| 存档体积  | 21 个数 + 槽位                   | 26 座实例，实测 12.7 KB，无影响          |
| UI    | 21 个建筑各一个面板                  | 需「建筑列表 + 实例详情」两级导航             |

#### 结论

**已决：采用多实例。**

落地于规划书 §4.1：`Planet.buildings: BuildingInstance[]`，单实例等级上限 16、同类型实例上限 8、单类型槽位上限 128、全星球实例上限 64。合计口径与成本口径同步写入。改造按 §14.1 的四步顺序执行，先加适配层再换结构。

### C4 等级语义不统一

§4.1 定「建筑等级决定槽位数量」，但实际有四种语义：

| 语义   | 建筑                                |
| ---- | --------------------------------- |
| 槽位   | 矿井、抽水站、油井、石炉、电炉、装配机、化工厂、炼油厂、实验室   |
| 输出功率 | 火力发电厂、太阳能阵列、核反应堆                  |
| 容量   | 蓄电器、仓库、物流塔                        |
| 特殊   | 城墙（防线时长）、雷达（情报层级）、炮塔（伤害）、发射井（并行数） |

**修法**：§4.1 改为「生产类建筑等级 = 槽位；其余按类型定义」，并在 §4.2 逐条标出。

### C5 城墙无损耗

§8.4 定「防线 = 基础 + 城墙等级 × 20 秒」，未定义消耗。城墙成为一次性永久投资，且 §8.9 定「失败不损失建筑」，防线只增不减。

**修法**：城墙每波次按「本波实际承伤」扣除耐久，耐久归零则该段失效，需消耗城墙段修复。

### C6 采掘建筑与矿脉的绑定关系未定义

§4.2 定「矿井槽位 = 可同时开采的矿种数」，但未定义：

- 矿井是否绑定某一具体矿脉
- 同一矿种能否堆多座矿井
- 油井的「累计开采」按矿脉计还是全局计

无空间布局的前提下，若不绑定，矿脉退化为全局数字；若绑定，则需要矿脉清单。

**修法**：矿脉定义为「每种矿一个全局储量」，矿井按槽位选择矿种，同一矿种可被多座矿井同时开采。储量扣除按该矿种全部矿井的合计产出结算。

### C7 周目重玩成本

12 周目 × 55 小时 = 660 小时。载荷继承仅 5 项，不足以支撑重复。

**修法**：定义周目加速规则。

| 继承项  | 效果                                   |
| ---- | ------------------------------------ |
| 数据核心 | 科技继承，直接跳过前 2 层                       |
| 工业种子 | 保留建筑等级，省去重建时间                        |
| 周目系数 | 第 N 周目全局产能 ×(1 + 0.1 × (N-1))，缩短单轮时长 |

## D 类 · 体验风险

### D1 缺 session loop（已解决，用战役承担）

文档定义了系统，未定义「玩家一次登录做什么」。当前唯一的持续操作是槽位分配，其余全是等待。

**决策：用现有战役系统承担，落地于规划书 §10。**

现有战役实测规模：

| 项    | 现状                                                 | 需要             |
| ---- | -------------------------------------------------- | -------------- |
| 章节   | 7                                                  | 7              |
| 每章任务 | 5~6                                                | 15~20          |
| 任务总数 | 36                                                 | 121            |
| 平均密度 | 每 1.5 小时 1 个                                       | 每 20~30 分钟 1 个 |
| 目标类型 | 6 类中 4 类失效（NPC / 外交 / 殖民 / 摧毁）                     | 改为工厂维度 10 类    |
| 奖励字段 | 已有 `unlockBuilding` / `unlockTech` / `specialItem` | 直接可用           |

需三处改造：

1. 任务表从 36 条扩到 121 条，目标改为 §10.3 的十类。
2. 主面板顶部常驻当前任务与进度条，不放在独立页面。
3. 奖励优先给解锁与稀有材料，资源类降为兜底。

单次登录的三件事：

```
1. 看主面板任务进度 → 完成 1~2 个子目标
2. 看诊断面板 → 找到 1~2 处红色 → 改槽位或升建筑
3. 打 1~2 波锈群 / 处理市场挂单
```

### D2 主动操作占比过低

槽位分配是低频决策（产线失衡才需要动）。50 小时里玩家大部分时间无事可做。

**修法**：增加一个高频决策点，建议「配方切换」：同一槽位可临时改跑其他配方，用时 10 秒，期间停产。用于应对突发需求（如偷袭前赶弹药）。

### D3 观看模式时长与定位冲突

10 波 × 30 秒 + 9 个间隙 × 30 秒 ≈ 9.5 分钟。挂机游戏要求一次主动投入 10 分钟偏高，且断线处理未定义。

**修法**：

- 单次挑战限制 5 波，约 4 分钟。
- 断线视为暂停，重新登录后从当前波继续，间隙计时暂停。

### D4 中期目标梯度缺失

除火箭外只有科技树，且科技树只给了数量。第 10~40 小时缺明确里程碑。

**修法**：把 42 项科技按「解锁一个新产品」重新组织，每层承诺一个可见的质变（新建筑 / 新流体 / 新弹药），并在 UI 上做成进度条。

### D5 完全可预测

纯数值、无随机，玩家可以算清一切。缺少「意外」。

**修法**：加入三类低强度随机，不惩罚离线。

| 事件     | 频率      | 效果         |
| ------ | ------- | ---------- |
| 矿脉发现   | 每 2 小时  | 某矿储量 +15%  |
| 市场波动   | 每 30 分钟 | 某材料价格 ±20% |
| 自由舰队来访 | 玩家触发    | 限时高价收购某材料  |

### D6 十人市场无流动性

10 名玩家各建各的，某材料可能长期无卖单。缺少做市机制。

**修法**：矿业公会持有常驻买卖盘，价格按基础价 ±10% 浮动，深度上限 5000 单位/种，玩家单永远优先于派系单成交。

### D7 客户端刷新未定义

诊断面板约 45 行 × 每行 5 个字段，若每 tick 重渲染，Vue 压力大且视觉抖动。

**修法**：面板 2 秒刷新一次，数值变化用补间动画过渡；状态枚举变化立即刷新。

## E 类 · 工程风险

### E1 存档迁移无方案

旧存档为 25 种建筑等级 + 3 种资源，新体系为 22 种建筑槽位 + 57 种材料。

**修法**：定义迁移映射表，一次性脚本处理。

```
旧 metal      → 铁矿石    1:1
旧 crystal    → 铜矿石    1:1
旧 deuterium  → 水        1:1       （若采用 A7 方案 1）
旧 building[type].level → 新实例 ×1，level 保留，槽位按新表换算
未映射建筑（大学 / 地形改造器 / 导弹发射井 …）→ 折算为等值铁板
```

### E2 建筑多实例改造影响面

若采用 C3 多实例，`buildings: Record<BuildingType, number>` 的引用遍布 `buildingLogic` / `resourceLogic` / `pointsLogic` / `protocol` / 多个 View。

**修法**：先加适配层 `getBuildingLevel(planet, type)` 与 `addBuilding(planet, type)`，把引用收敛到两个函数后再改数据结构。

### E3 战役目标类型失效

现有 `ObjectiveType` 中以下目标在新体系下失效：

| 目标                                            | 状态         |
| --------------------------------------------- | ---------- |
| `DefeatNPC`                                   | 失效，NPC 已删除 |
| `ReachRelation` / `SendGift` / `FormAlliance` | 失效，改为派系声望  |
| `Colonize`                                    | 失效，单母星     |
| `WinBattles`                                  | 改为「通过 N 波」 |
| `DestroyPlanet`                               | 失效         |

7 章战役需重写目标定义。

### E4 i18n 债务

新增约 400 key × 8 语言 = 3200 条。其中 de / ru / ko / ja / es 五个语言包当前已有大量英文占位。

**修法**：新 key 只保证 zh-CN 与 en 完整，其余语言标记 `TODO`，`check:i18n` 允许 `TODO` 通过但统计数量。

### E5 报告上限与成就冲突

战报上限 30 份。若任何成就或战役统计依赖「历史战报总数」，截断后统计失真。

**修法**：成就统计改用独立计数器（`totalBattlesWon`），不读报告数组。
