## プロジェクト概要

**OGame Vue TS · マルチプレイ再構築版**は、原作者 [setube](https://github.com/setube) のオープンソースプロジェクト [ogame-vue-ts](https://github.com/setube/ogame-vue-ts) を基に二次開発した宇宙戦略ゲームです。

本プロジェクトは原作のシングルプレイの遊び方と中核となる数値体系を維持しつつ、マルチプレイ用のアーキテクチャ、UI 操作、銀河ビュー、基地システム、デプロイ方式などを大幅に再構築・拡張しています。

現在のバージョンでは、次の 2 つの実行モードを提供しています：

- **シングルプレイモード**：ゲームのコアがブラウザ内で動作し、セーブデータはローカルに保存されるため、すぐに遊べます；
- **マルチプレイモード**：Node.js WebSocket サーバーを唯一の正となる状態ソースとし、アカウント、多人数同時接続、PvP、チャット、ランキング、NPC エコシステムをサポートします。

> 本プロジェクトが現在メンテナンスしているのは、**Web 版 + 飛牛 fnOS Docker** のデプロイ方式のみです。Android、Electron、Go サーバーなどの旧デプロイ形態は削除済みで、関連するコードは Git の履歴から確認できます。

## 主な機能

### 基地と帝国の運営

- 建物・研究・造船所・防衛の 4 つの主要モジュールを 1 つの基地に統合；
- 建物キュー、研究キュー、艦隊ミッションスロット、資源消費をリアルタイムで計算；
- 月面基地、月の生成、デブリフィールド、回収メカニズム；
- 士官システム、資源ボーナス、帝国ポイント、複数惑星の管理。

### 艦隊と戦闘

- 艦船の建造、艦隊編成、ミッション派遣、多段階航行；
- 戦闘シミュレーター：資源を投入する前に艦隊構成を検証可能；
- 戦闘レポート、戦利品、デブリフィールド、攻撃・防衛の精算；
- 星門の占領、通行料、封鎖、NPC 商隊。

### 外交と NPC エコシステム

- NPC との関係、評判、貿易、贈り物、情報、外交イベント；
- 敵対 NPC による偵察、攻撃、報復行動；
- NPC の成長、経済生産、複数プレイヤーが共有する世界；
- 外交通知、イベントレポート、関係ステータスによる絞り込み。

### 銀河と探索

- 全画面 2.5D 星図、恒星系／ローカル星団／銀河全体の 3 段階ビュー；
- 10 個の惑星が恒星の周囲をゆっくり公転し、軌道・大きさ・速度はランダム；
- 惑星または恒星系をクリックするとフォーカスし、カメラが追従してコンテキストパネルがフェードインする；
- スキャン、命名、星門、未知の信号、ワームホール、残骸、遺跡の探索；
- 12 サイクル × 16 星域 × 64 恒星系からなる周期的な宇宙。

### マルチプレイと長期運営

- アカウント登録、ログイン、セッション、切断後の再接続；
- サーバー権威型の世界を採用し、クライアントはコマンドと状態パッチで同期；
- プレイヤー間取引、PvP、偵察、ミサイル、艦隊ミッション、リアルタイム通知；
- パブリックチャット、個人チャット、オンライン状態、ランキング、シーズン／サイクルの仕組み；
- サーバー側の JSON セーブデータ、自動保存、Docker データボリュームによる永続化。

### ユーザー体験と保守性

- 8 言語：簡体字中国語、繁体字中国語、English、Deutsch、Русский、Español、한국어、日本語；
- ダーク／ライトテーマ、レスポンシブレイアウト、PWA；
- シングルプレイのセーブデータを IndexedDB に永続化；
- 統一されたコマンド層、ヘッドレスコア、テスト可能なゲームルール層；
- 飛牛 fnOS Docker によるワンクリックデプロイとイメージのエクスポート。

## シングルプレイとマルチプレイのアーキテクチャ

```text
┌────────────────────────────────────────────────────┐
│                ブラウザクライアント                │
│  Vue 3 + Pinia + Vue Router + Tailwind CSS         │
│  ビュー層はコマンド発行のみ、状態は直接変更しない  │
└─────────────────────────┬──────────────────────────┘
                          │
             ┌────────────┴──────────┐
             │                       │
      シングルプレイ            マルチプレイ
             │                       │
             ▼                       ▼
┌──────────────────────────┐     WebSocket
│  src/core                │         │
│  ヘッドレスゲームコア    │         ▼
│  tick / コマンド         │     Node.js サーバー
│  ルール / 状態           │     server/ + ws
└────────────┬─────────────┘         │
             │                       ▼
             ▼                   サーバー権威型の世界
         IndexedDB               data/world.json
```

- `src/core`：ヘッドレスゲームコア。世界状態、tick、ミッション、NPC、コマンド、プロトコルを担当；
- `src/logic`：純粋なゲームルールと数値計算。UI への依存をできるだけ排除；
- `server/`：Node.js WebSocket サーバー、アカウント、ルーム、永続化、静的リソースのホスティング；
- `src/stores` / `src/views`：ブラウザ側の状態管理と UI；
- `scripts/`：ヘッドレススモークテスト、サーバーテスト、ビルドスクリプト。

シングルプレイモードはヘッドレスコアをそのまま再利用します。マルチプレイモードではサーバーが同じコアロジックを実行し、クライアントはコマンドの送信とスナップショットの描画のみを担当します。

## クイックスタート

### 動作環境

- Node.js **22+**
- pnpm **10+**
- モダンブラウザ（Chrome / Edge / Firefox / Safari）

### クローンとインストール

```bash
git clone https://gitee.com/shilianlvke/ogame-vue-ts.git
cd ogame-vue-ts
pnpm install
```

GitHub ミラー：

```bash
git clone https://github.com/shilianlvke/ogame-vue-ts.git
```

### ローカル開発

```bash
pnpm dev
```

デフォルトの開発 URL：

```text
http://localhost:25121
```

### 本番ビルド

```bash
pnpm build
pnpm preview
```

`pnpm build` は最初に TypeScript の型チェックを実行し、その後フロントエンドの静的リソースを `docs/` にビルドします。

### マルチプレイサーバーをローカルで起動

```bash
# フロントエンドと Node サーバーをビルド
pnpm build
pnpm run build:node-server

# サーバーを起動（デフォルトで docs/ と data/ を読み込む）
pnpm start:server
```

デフォルトのポートは `25122` で、環境変数で上書きできます：

```bash
PORT=8080 STATIC_DIR=docs DATA_DIR=data pnpm start:server
```

サーバー起動後：

- ゲーム画面：`http://localhost:25122`
- ヘルスチェック：`http://localhost:25122/health`
- WebSocket：`ws://localhost:25122/ws`

> 本番環境では HTTPS/WSS を使用し、アクセス制御、バックアップ、セキュリティ強化を各自で行ってください。

## マルチプレイのデプロイ

現在は飛牛 fnOS の Docker によるデプロイ方式を推奨しています。

### 方法 1：飛牛のソースからワンクリックデプロイ（推奨）

前提条件：飛牛に Docker と git がインストールされていること。また、`node:22-alpine` を取得できるか、レジストリミラーが設定されていること。

```bash
cd /vol1/docker
git clone https://gitee.com/shilianlvke/ogame-vue-ts.git ogame
cd ogame

chmod +x deploy-fnos.sh
./deploy-fnos.sh
```

以降の更新：

```bash
./deploy-fnos.sh --update
```

その他のコマンド：

```bash
./deploy-fnos.sh --start
./deploy-fnos.sh --stop
./deploy-fnos.sh --restart
./deploy-fnos.sh --logs
./deploy-fnos.sh --status
./deploy-fnos.sh --port 8080
./deploy-fnos.sh --china
```

### 方法 2：PC でイメージをビルドしてインポート

Windows：

```powershell
.\docker-build.ps1
```

このスクリプトは `noskyman:latest` をビルドし、`noskyman.tar` をエクスポートします。`noskyman.tar` と `docker-compose.yml` を飛牛の同じディレクトリにアップロードした後、次を実行します：

```bash
docker load -i noskyman.tar
docker compose up -d
```

詳細な説明、環境変数、リバースプロキシ経由の WebSocket 設定、よくある質問については、以下をご覧ください：

- [飛牛 fnOS Docker デプロイガイド](DEPLOY_DOCKER.md)

> `docker-compose.yml` はローカルの `noskyman:latest` イメージのみを使用し、自らネットワークから取得することはありません。ソースからのビルドは `deploy-fnos.sh` が行います。

## プロジェクト構成

```text
.
├── src/
│   ├── core/          # ヘッドレスゲームコア：世界、tick、コマンド、ミッション、NPC、プロトコル
│   ├── logic/         # 純粋なゲームルールと数値計算
│   ├── components/    # Vue コンポーネント
│   ├── views/         # ページビュー
│   ├── stores/        # Pinia ストア
│   ├── locales/       # 8 言語の文言
│   ├── services/      # セーブ、更新、WebDAV などのサービス
│   └── workers/       # 戦闘 Worker
├── server/            # Node.js WebSocket サーバー
├── scripts/           # ビルド、i18n、ヘッドレス／サーバーのスモークテスト
├── doc/               # デプロイ、マルチプレイ、銀河設計、リファレンス
├── public/            # 静的リソース
├── Dockerfile         # フロントエンド + Node サーバーのマルチステージイメージ
├── docker-compose.yml # 飛牛の実行構成
├── deploy-fnos.sh     # 飛牛ワンクリックデプロイスクリプト
└── docker-build.ps1   # Windows でのイメージビルドとエクスポート
```

## よく使うスクリプト

| コマンド | 説明 |
|---|---|
| `pnpm dev` | Vite 開発サーバーを起動 |
| `pnpm build` | 型チェックを実行し、フロントエンドを `docs/` にビルド |
| `pnpm preview` | 本番ビルドをプレビュー |
| `pnpm typecheck` | TypeScript の型チェック |
| `pnpm check:i18n` | 8 言語パッケージのキーを検証 |

| `pnpm smoke` | ヘッドレスエンジンのスモークテスト |
| `pnpm smoke:server` | 実際の WebSocket サーバーとの統合テスト |
